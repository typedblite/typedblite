## What you get

<CardGrid>
  <Card title="No server to run" icon="seti:json">
    It runs inside your process: on Node.js with the built-in `node:sqlite`, and in a browser on WASM SQLite.
    You keep the polymorphic type model, the schema-first design and the query language.
  </Card>
  <Card title="Offline-first sync" icon="random">
    Every write goes in a change log. Stores replicate hub-and-spoke and converge without conflict when two
    nodes make the same edit, and a conflicting edit is kept, not discarded.
  </Card>
  <Card title="Measured, not claimed" icon="approve-check">
    It passes 1,742 of the 1,756 scenarios in TypeDB's own behaviour specification. Twelve of the 14 that do not
    pass also fail on TypeDB itself.
  </Card>
  <Card title="An editor and a playground" icon="laptop">
    A VS Code extension with a Langium language server, and a browser playground that runs the same
    language server over LSP.
  </Card>
</CardGrid>

## A schema, a write, a query

<Tabs>
  <TabItem label="Schema">
```typeql
define
  entity book, owns title @key, owns author, owns status;
  attribute title, value string;
  attribute author, value string;
  attribute status, value string;
```
  </TabItem>
  <TabItem label="Write">
```typeql
insert $b isa book,
  has title "Dune",
  has author "Frank Herbert",
  has status "to-read";
```
  </TabItem>
  <TabItem label="Query">
```typeql
match $b isa book, has title $t, has author $a, has status $s;
select $t, $a, $s;
sort $t;
```
  </TabItem>
  <TabItem label="From Node">
```js
import { TypeDBLiteInterpreter } from '@typedblite/runtime';

const db = new TypeDBLiteInterpreter('readlist.db'); // a file is a database
const { rows } = db.query(`
  match $b isa book, has title $t, has author $a;
  select $t, $a;
`);
for (const row of rows) console.log(row.t.asString(), 'by', row.a.asString());
db.close();
```
  </TabItem>
</Tabs>
