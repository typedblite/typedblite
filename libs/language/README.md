# @typedblite/language

Langium grammar, generated AST, and language services for **TypeQLite** — the TypeQL 3.x dialect that TypeDBLite speaks.

## What this package provides

- **Grammar** (`src/typeqlite.langium`) — the authoritative Langium grammar definition for TypeQLite 3.x.
- **Generated AST** (`src/generated/ast.ts`) — typed node interfaces and `is*` / `as*` type guards for every grammar production, generated by `langium generate`.
- **Module** (`typeqlite-module.ts`) — Langium DI container with all TypeQLite services wired up.
- **Synchronous validation** (`typeqlite-validate-sync.ts`, `typeqlite-validator.ts`) — parse-time constraint checks that run synchronously, as the runtime requires.
- **Validation codes** (`typeqlite-validation-codes.ts`) — stable string identifiers for every validation rule; consumed by the runtime's `DiagnosticCode` to avoid a parallel vocabulary.
- **Annotation admissibility** (`typeqlite-annotations.ts`) — table of which annotations are valid at which positions (type, `sub`, trait, value type).
- **Scope provider** (`typeqlite-scope.ts`) — resolves cross-references; role names are scoped to their relation, so two relations may each `relate member`.
- **Formatter** (`typeqlite-formatter.ts`) — canonical formatting for `.typeqlite` files.
- **Semantic tokens** (`typeqlite-semantic-tokens.ts`) — token classifications for editor syntax highlighting.
- **TextMate grammar** (`syntaxes/typeqlite.tmLanguage.json`) — for editors that use TextMate grammars rather than a language server.

## Installation

This package is part of the TypeDBLite monorepo. It is consumed as a workspace dependency by `@typedblite/runtime`.

```bash
npm install
npm run build   # or: nx run @typedblite/language:build
```

## Usage

```ts
import { createTypeQLiteServices, validateSync } from '@typedblite/language';
import { EmptyFileSystem } from 'langium';

const services = createTypeQLiteServices(EmptyFileSystem);

// Parse and validate in one step
const { ast, diagnostics } = validateSync(services, `
  define
    entity person, owns name @key;
    attribute name, value string;
`);
```

The returned `ast` is a fully linked `TypeQLiteFile` — cross-references are resolved and type guards like `isEntityDef`, `isOwnsTrait`, `isKeyAnnotation` work against every node.

## Regenerating the AST

The generated files in `src/generated/` are outputs of `langium generate` and must be committed alongside any grammar change.

```bash
cd libs/language
npm run langium:generate
# Commits: src/typeqlite.langium  +  src/generated/{ast,grammar,module}.ts
```

Do not edit `src/generated/` by hand — changes are overwritten on the next generation.

## Synchronous validation

Langium wraps every registered validation check in an `async` function internally. `SyncValidationRegistry` overrides that wrapper to keep the check's own synchronous result synchronous. The runtime calls `validateSync`, which never returns a `Promise`. A rule that returns a `Promise` is surfaced as a validation error rather than silently awaited.

## Grammar scope

TypeQLite 3.x implements the subset required by real production schemas and by TypeDB's behaviour specification (`typedblite-conformance/spec/`). A construct is added only when a real caller needs it. The rule is:

> Find the caller first. What is here is what callers use — not what TypeDB has.

## Tests

```bash
nx run @typedblite/language:test
```

Test files live in `test/` with `.spec.ts` extension. The spec-backgrounds suite (`test/spec-backgrounds.spec.ts`) uses the vendored TypeDB behaviour specification as acceptance tests for the grammar.
